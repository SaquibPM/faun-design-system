## When to use

- Beside a disclosed number, so an auditor can see where it came from and what happened to it.
- When a value passed through machines and people: an extraction, a factor, a calculation and a review.

## When not to use

- To show the work an agent did in a run. Use [Run trail](/components/run-trail).
- To cite a statement in running text. Use [Citation](/components/citation).
- For who edited a record over time. Use [Timeline](/components/timeline).

## Writing

- Titles say what happened: “Consumption read from the bills”, not “Extraction”. The kind label is added for you.
- Put units on every value. Use tabular figures and the same unit style as the rest of the page: tCO₂e, MWh.
- End with the datapoint as it appears in the disclosure, including its ESRS reference.

## Anatomy

An ordered list joined by a line. Each node has a marker with the kind's icon, a kind label, a title, the value it carried, optional detail, and a line naming who or what did it, the source and when. The final reported value is set in the display face on a moss marker.

## Colour

Machine steps (extraction, factor, calculation) are lagoon. Human review is plum. Estimates are warning. Sources are neutral. Each node also names its kind in words.

## Notes

- Nodes are `ProvenanceNode` objects, in order from source to reported value. The last node is styled as the result.
- `value` is pre-formatted text so you control rounding and units.
- Give the list an `aria-label` that names the figure.

## Screen readers

- An ordered list, so the order is announced. Each node starts with its kind as text.
- Marker icons are decorative. Times use the `time` element with a machine-readable value.

## Visual

- Estimates are labelled “Estimated” with a warning icon. Colour never carries the meaning alone.
