## When to use

- When an agent pre-fills something a person owns: a field, a paragraph, a card of findings.
- When the person must be able to see at a glance what has been accepted and what has not.

## When not to use

- For content that is fully automatic and never reviewed. Mark it with an [AI label](/components/ai-label) only.
- For a decision that gates a run. Use [Approval card](/components/approval-card).
- For a whole conversation. Use [AI chat](/components/ai-chat).

Buttons: Accept, Edit, Revert to AI version. The label: “AI suggested”, then “AI generated”, then “AI generated, edited”.

## Anatomy

A frame around the control with the AI label above it, and an action row below. A suggestion is tinted with `ai.bg` and has a dashed `ai.border`; accepted content returns to the plain surface; edited content has a subtle outline. Inputs and text areas inside a suggestion sit on the surface colour so text stays legible.

## Notes

- You own the state: `onAccept` sets `accepted`; change `state` to `edited` when the value differs from the AI original; `onRevert` restores the value and sets `accepted`.
- `explain` is passed to the AI label: `agent`, `model`, `summary`, `confidence`, `sources`, `actions`.
- `labels` renames the label per state; `acceptLabel`, `editLabel` and `revertLabel` rename the buttons.
- Edit calls `onEdit` and focuses the first input, textarea, select or editable element inside.

## Screen readers

- State changes are announced politely: “Suggestion accepted.”, “Edited. You can revert to the AI version.”
- The label button names the state in words, so the tint is not the only signal.

## Visual

- A suggestion is marked by a dashed border and a label as well as a tint, so it survives forced colours and colour-blindness.
