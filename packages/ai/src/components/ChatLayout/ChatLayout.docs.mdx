## When to use

- For a full-height conversation with an agent that can also show progress and make things.
- Inside the page area of an [App shell](/components/app-shell), so the left navigation, which belongs to the shell, can open or collapse around it. The [Chat with panels pattern](/patterns/chat-with-panels) shows all three together.

## When not to use

- For a one-off question box on a dashboard. Use [Prompt composer](/components/prompt-composer) and [AI chat](/components/ai-chat) directly.
- For a run viewer that is not a conversation. Use the [Agent run viewer pattern](/patterns/agent-run-viewer).

## Writing

- The header names the conversation, not the product. Keep it to one line.
- Open panels from the message that makes them useful: a button in the message that says “Open the draft”, a link on the progress card. Do not open them without being asked, except the first time work starts.

## Anatomy

The main column holds the header, the scrolling thread (centred to the reading width) and the composer. The panel column sits on its right: the progress panel on top when both are open, the artifact below it. The column is as wide as the artifact panel, or 320 px for the progress panel alone.

## Behaviour by width

- 768 px and wider: panels dock beside the thread. The artifact can be resized and maximised.
- Under 768 px: the artifact is a full-screen sheet, the progress panel a bottom sheet. The thread is inert while either is open.

## Notes

- Render `progress` and `artifact` to open them and leave them out to close them. The layout does not keep that state; your header toggles do. `ChatLayoutControls` is a pair of pressed-state buttons for it.
- The layout measures itself, not the window, so it also works inside a small frame.
- `useChatLayout()` gives custom panels the same width, compact and maximised state that `ArtifactPanel` uses.
- Put the layout in a parent with a height. It fills it and scrolls only the thread.

## Screen readers

- The thread column is a region named by `label`. Panels are regions named by their titles.
- Header toggles are buttons with `aria-pressed` and a label that says what the next press does: “Show progress panel”, “Hide progress panel”.
- While a panel is a sheet the thread is `inert`, so focus cannot reach it. When it closes, focus returns to the control that opened it.

## Visual

- Panels are separated from the thread by a hairline, and by a scrim for the progress sheet.
- Forced colours: the dividers use the system text colour.
