## When to use

- Above a table or list where people narrow results by several attributes: scope, framework, data quality, owner.
- When applied filters must stay visible, so nobody misreads a filtered list as the whole set.

## When not to use

- For one or two always-present toggles. Use FilterChip or a SegmentedControl.
- For free text search alone. Use SearchField.
- For switching between views of the same data. Use Tabs.

## Anatomy

Chips (Tag with a remove button), the Add filter button, Clear all (once any filter is applied) and an optional slot for extra controls. Everything wraps on narrow screens.

## Notes

- A filter is `{ field, value }`. Define the choices once in `fields`, each with its `options`.
- Controlled with `value` and `onValueChange`, or uncontrolled with `defaultValue`.
- Filters whose field or option is not in `fields` are ignored, so a stale URL cannot break the bar.

## Screen readers

- The bar is a group named “Filters”. Chips are list items; each remove button is named in full, for example “Remove filter Scope: Scope 1”.
- Options are menu checkboxes, so applied options are announced as checked.
- A polite status announces the count: “2 filters applied”, “No filters applied”.

## Visual

- Chips show field and value as text. Focus rings use the focus token.
