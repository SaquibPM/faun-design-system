## When to use

- To compare many records across the same attributes: CSRD datapoints, suppliers, agent runs, evidence items.
- When people sort, scan and select rows rather than read each one in turn.

## When not to use

- For one record with many attributes. Use a description list.
- For a handful of figures that lead a page. Use a Stat row.
- For layout. A table holds data, not page structure.

## Writing

- Column headers are short nouns in sentence case. Put the unit in the header (“Value (tCO₂e)”) when every cell shares it.
- Show a dash for no value, never a blank. For a missing or estimated figure use a DataQualityCell so the reason is visible.
- Name the table with a label that says what the rows are: “CSRD datapoints”, not “Table”.

## Notes

- `columns` describe the table; `data` is the rows to show. Filtering and fetching stay with you, so the table works with a client array or a server query.
- Pagination: `paginated` pages client-side (sorting happens first, then the slice). With `totalRows` the table is server-driven: `data` is the current page, `page` and `pageSize` are yours to control, and the table sets `aria-rowcount` and absolute `aria-rowindex`. Both modes use the Pagination component and a polite announcement on page change. Row ids must be stable across pages if you use `getRowId`.
- Expandable rows: `renderExpanded` returns the detail; control with `expandedIds` and `onExpandedIdsChange`. Detail rows are not counted in `aria-rowcount`.
- Column menu: control with `hiddenColumns` and `onHiddenColumnsChange`, or start from `defaultHiddenColumns`. A hidden column keeps sorting if it was the active sort.
- Virtualisation: set `maxHeight` so the table scrolls, keep cell content to one line, and use `virtualize` for thousands of rows rather than for tens. Rows are positioned by a measured height, so density still applies. It is ignored (with a console warning) together with `paginated` or `renderExpanded`; prefer pagination when people need to jump to a place in the data.
- Give every row a stable id with `getRowId`. Selection is stored as ids and survives sorting.
- Sorting cycles ascending, descending, off. Empty values sort last in both directions, and text sorts numerically aware (“E1-5.38” before “E1-6.44”).
- A column's `cell` renders anything, including a DataQualityCell, a Tag or a link. Use `sortValue` when the displayed value is formatted.
- Single select: `selectable` with `selectionMode="single"`. `selectedIds` holds at most one id. The radios are native inputs sharing one name; the arrow keys move between rows (not between radios), and Space chooses.
- Toolbar: `toolbar` renders above the rows. `DataTableToolbar` lays out `search`, `filters` and `actions` (build them from `SearchField`, `FilterChip`, `Button`). While rows are selected in multiple mode the strip is hidden (its state, such as a search term, is kept) and the selection bar is shown instead.
- Row size: `rowSize` (or `defaultRowSize` with `onRowSizeChange`), or `rowSizeMenu` for a picker in the toolbar. Sizes xs and sm suit read-only scanning; the sort and expand buttons keep their target size.
- Row actions: put `DataTableRowActions` in a column's `cell`. Pass the same text you use for `getRowLabel` as `label` so every button has a distinct name. `reveal="always"` keeps them visible.
- Sticky first column needs a table wider than its container (resizable columns, or many columns). The first data column keeps the row-header role.
- `onRowActivate` makes rows focusable with a roving tab stop. Enter or a click on the row (outside its buttons and links) calls it.

## Screen readers

- A native table with a name from `label`, column headers with `scope="col"`, and `scope="row"` on the column marked `rowHeader`.
- Sortable headers expose `aria-sort`. The sort button's text says what it will do next.
- Each row checkbox is named from `getRowLabel`, for example “Select E1-6.44 Gross Scope 1 GHG emissions”. The selected count is a polite live region.
- Expand buttons carry `aria-expanded`, `aria-controls` (when open) and a name such as “Expand details for E1-6.44”. The detail is a labelled group directly below its row.
- The column menu is a menu of checkable items; the last visible column is disabled so the table is never empty.
- With pagination or virtualisation the table has `aria-rowcount` for the full size and every row has `aria-rowindex` (the header is row 1), so assistive technology reports “row 2,001 of 5,001” even though only a window is in the DOM. Page changes are announced politely.
- In single-select mode each row has a radio named from `getRowLabel`; the header cell carries a hidden “Select a row”. Row action buttons are named with the row (“Edit E1-6.44”, “Actions for E1-6.44”); hover-reveal only changes opacity, so the buttons stay in the tab order and appear when focused.
- Loading sets `aria-busy` and announces “Loading …”. Empty and error states are headings with text, not just icons.
- The scroll area is a labelled region and can be focused, so keyboard users can scroll wide tables.

## Visual

- Row actions are visible on touch screens and in forced-colours mode; they only hide on hover-capable pointers until the row is hovered, focused or the menu is open.
- Selected, hovered and focused rows are distinguishable without colour: selection is also shown by the checked box.
- Focus rings follow the focus token and stay inside the scroll area.
- Targets in the header and checkboxes meet the minimum target size.
