## When to use

- For quantities with a unit: fuel in litres, water in m³, emissions in tCO₂e.
- For values with limits, such as a percentage between 0 and 100.

## When not to use

- For identifiers made of digits, such as account numbers. Use [Input](/components/input).
- For picking a rough value. Use [Slider](/components/slider).

## Writing

State bounds in the description or error: “Enter a value between 0 and 100.” Do not use words for numbers.

## Warn, read-only and loading

<Example of="NumberField/StateContract" title="Warn, read-only and skeleton" description="Warn marks a value that is allowed but worth a second look. It is never the same as invalid: it does not set aria-invalid and never blocks submission, and the message carries an icon and text so it is not colour alone. Read-only shows the value flat, keeps it focusable and copyable, and ignores changes. Skeleton replaces the control while its data loads; the label stays for screen readers. Set all three on a Field and every control inside follows." />

Set `warn` (a message), `readOnly` and `skeleton` on the surrounding `Field`. On a standalone number field, pass `readOnly` and `skeleton` directly; give `warn` a message through a Field so it is announced. An error always replaces a warning.

## Anatomy

An input with right-aligned tabular figures, an optional prefix and unit, and optional stepper buttons. The displayed number is formatted for the locale and parsed back when it loses focus.

## Notes

- `value` is `number | null`. `min`, `max` and `step` clamp the value.
- `locale` and `formatOptions` use `Intl.NumberFormat`.
- The field never rejects typing. It clamps and formats on blur.
