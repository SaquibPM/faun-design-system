## When to use

- To confirm or complete one short task that needs the person's full attention: submit for approval, name a snapshot.
- When the task must finish or be cancelled before the person goes back to the page.

## When not to use

- To confirm destruction or an irreversible action. Use [Alert dialog](/components/alert-dialog), which needs an explicit choice.
- For long forms or detail the person needs next to the page. Use [Sheet](/components/sheet).
- For small contextual content tied to a control. Use [Popover](/components/popover).

## Writing

- Title is a question or a verb phrase: “Submit the CSRD statement?”.
- Description says the consequence in one or two sentences.
- Buttons repeat the action: “Submit for approval”, not “OK”.

## Anatomy

Scrim, panel, header (optional icon, title in the display face, description), scrolling body, footer (start slot and end-aligned actions) and a close button.

## Sizes and layers

Panels use the extra large radius, elevation 5 and the modal layer. The scrim fades over the slow duration and the panel scales in.

## Notes

- `Dialog` is the Radix root: control it with `open` and `onOpenChange`.
- `DialogHeader` requires a title. Without a description it adds a hidden one so assistive technology has a name and a description.
- Use `DialogClose asChild` around buttons that should close the dialog.
- `variant` is `default`, `passive` or `danger`. `size` is `xs`, `sm`, `md`, `lg` or `xl`. Set `scrollLabel` on `DialogBody` to name the content when it scrolls.

## Screen readers

- Announced as a dialog named by its title and described by its description. Content behind it is inert. A body that overflows is exposed as a labelled region (`scrollLabel`) so it can be reached and scrolled with the keyboard; a short body is not a region.

## Visual

- The close button is labelled and meets the minimum target size. The scrim keeps the panel at 3:1 against the page.
