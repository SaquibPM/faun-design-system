## When to use

- For short free text: names, identifiers, references, URLs.
- Use `numeric` for figures that must line up, with a unit in the suffix.

## When not to use

- For numbers with steppers and bounds. Use [Number field](/components/number-field).
- For longer text. Use [Textarea](/components/textarea).
- For finding things. Use [Search field](/components/search-field).
- For choosing from a list. Use [Select](/components/select) or [Combobox](/components/combobox).

## Writing

Labels name the thing in sentence case. Errors say what is wrong and how to fix it: “Enter a year between 2015 and 2026.”

## Warn, read-only and loading

<Example of="Input/StateContract" title="Warn, read-only and skeleton" description="Warn marks a value that is allowed but worth a second look. It is never the same as invalid: it does not set aria-invalid and never blocks submission, and the message carries an icon and text so it is not colour alone. Read-only shows the value flat, keeps it focusable and copyable, and ignores changes. Skeleton replaces the control while its data loads; the label stays for screen readers. Set all three on a Field and every control inside follows." />

Set `warn` (a message), `readOnly` and `skeleton` on the surrounding `Field`. On a standalone text input, pass `readOnly` and `skeleton` directly; give `warn` a message through a Field so it is announced. An error always replaces a warning.

## Notes

- `Input` works on its own or inside a [Field](/components/field), which supplies the id, description and error wiring.
- `TextField` is Field plus Input. Pass `error` to mark it invalid, `warn` for a warning, `variant` for the inline or fluid layout.
- `Input` and the other form controls share one state contract: `warn`, `readOnly` and `skeleton` flow from `Field` through `useFieldControl`. Custom controls get the same by calling `useFieldControl(props, { warn, readOnly, skeleton })` and spreading `state.attrs` on the control box.

## Screen readers

- The label, description, warning and error are associated with the input. Errors are announced assertively and warnings politely when they appear.
- The password button has a fixed-position, named toggle; the counter is part of the input's description.

## Visual

- Borders meet 3:1 against the surface. Placeholder text is a hint only and never the label.
