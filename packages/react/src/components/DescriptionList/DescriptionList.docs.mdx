## When to use

- Facts about one thing: a datapoint, a run, an entity, an emission factor.
- In side panels, dialogs and card bodies where a table would be too heavy.

## When not to use

- Comparing many records: use a Table.
- Editable fields: use a form with Field and inputs.

## Anatomy

Rows of term (muted) and value (default colour). In the horizontal layout terms share a fixed column (`termWidth`). Values may be text, a badge or any node.

## Notes

- Renders a native `dl`, with each pair wrapped in a `div`, which is valid HTML and read correctly by screen readers.
- Copy uses the async clipboard API and fails silently where it's unavailable.

<Section tab="accessibility">

## Keyboard

<Keys rows={[["Tab", "Moves to copy buttons."], ["Enter / Space", "Copies the value."]]} />

## Screen readers

- Terms and values are announced as a list of term and definition pairs.
- Each copy button is named “Copy”, then “Copied” after use.

## Visual

- Muted terms meet 4.5:1 on the surface. Mono values use the code face at the same size as body text.
