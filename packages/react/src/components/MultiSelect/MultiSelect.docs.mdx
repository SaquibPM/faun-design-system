## When to use

- To choose several entities, sites or frameworks from a long list.
- When selections should be visible at a glance in the trigger.

## When not to use

- For up to about 6 options. Use a [Checkbox](/components/checkbox) group.
- For one value. Use [Select](/components/select) or [Combobox](/components/combobox).

## Warn, read-only and loading

<Example of="MultiSelect/StateContract" title="Warn, read-only and skeleton" description="Warn marks a value that is allowed but worth a second look. It is never the same as invalid: it does not set aria-invalid and never blocks submission, and the message carries an icon and text so it is not colour alone. Read-only shows the value flat, keeps it focusable and copyable, and ignores changes. Skeleton replaces the control while its data loads; the label stays for screen readers. Set all three on a Field and every control inside follows." />

Set `warn` (a message), `readOnly` and `skeleton` on the surrounding `Field`. On a standalone multi-select, pass `readOnly` and `skeleton` directly; give `warn` a message through a Field so it is announced. An error always replaces a warning.

## Notes

- `value` is a string array. `maxVisible` (default 3) controls how many tags show before “+N”.
- `bulkActions` (on by default) adds Select all and Clear to the footer.
- Options share the shape used by Select and Combobox.

## Screen readers

- The list is announced as multiselectable, and each option announces whether it is checked.
- Selected values are a list named “Selected”, and each remove button is named “Remove” followed by the value.

## Visual

- Selected options show a check in a box as well as a background, so selection never relies on colour.
