## When to use

- To start, confirm or cancel an action that happens on this page or in a dialog.
- To open an overlay (dialog, sheet, menu) that the user explicitly asked for.

## When not to use

- To navigate to another page: use a link. If it must look like a button, render a link with `asChild`.
- For on/off settings: use a Switch. For one choice among a few: use a Segmented control.
- For icon-only actions in toolbars and table rows: use an Icon button, which always carries a label and tooltip.

## Hierarchy

Every view has at most one primary action, usually the step that moves the work forward. Everything else steps down in emphasis.

## Writing labels

Labels say exactly what happens, as a verb plus an object, in sentence case. The action keeps its name through the flow: a button that says **Approve materiality** produces a toast that says **Materiality approved**.

## Anatomy

A button is a label with an optional leading icon, an optional trailing icon (usually a chevron for menus), and a loading spinner that replaces the content without changing the width.

## Flat by design

Buttons are flat: solid, soft, outline and ghost are a plain face with no extruded edge, no outline of their own and no texture (ADR 0008, which replaces the relief buttons of ADR 0006 and 0007). Hover and pressed shift the face one step, pressed also nudges it down half a pixel, and the focus ring is unchanged. Relief, with its wave texture, stays on chart marks. IconButton, MenuButton, ComboButton and ButtonGroup are flat too.

## Notes

- Defaults to `type="button"`, so a button inside a form never submits by accident. Pass `type="submit"` for the form's submit button.
- All native button attributes pass through. Refs forward to the underlying element.
- Group two or three related buttons with [ButtonGroup](/components/button-group). For a button that opens a menu use [MenuButton](/components/menu-button).
- Icons passed to `leadingIcon` and `trailingIcon` are hidden from assistive technology; the label carries the meaning.

## Screen readers

- The accessible name is the visible label. Don't override it with `aria-label` unless the label is ambiguous out of context.
- When `status` is set, `statusLabel` is added to the name ("Save Saved"), and the icon is hidden from assistive technology.
- While `loading`, the button sets `aria-busy="true"` and keeps its name, so the action is announced consistently.
- Disabled buttons use the native `disabled` attribute and leave the tab order. If people need to discover why an action is unavailable, keep the button enabled and explain on activation.

## Visual

- Labels meet 4.5:1 on every fill in every theme (7:1 in high contrast); the primary fill meets 3:1 against the page so its boundary is visible.
- Focus shows a 2px ring offset by 2px, meeting WCAG 2.2 focus appearance.
- Medium buttons are at least 28px tall in compact density, above the 24px target minimum.
