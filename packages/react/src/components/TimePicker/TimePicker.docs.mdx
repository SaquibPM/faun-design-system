## When to use

- To set a time of day: when a run starts, when a review closes, a cut-off.
- With a [Date picker](/components/date-picker) when you need both. Keep them as two fields, date first.

## When not to use

- For a duration (“2 hours”). Use a number field with a unit.
- For seconds or milliseconds. Use an Input with your own format.
- For a choice among a few named times (“Morning, afternoon”). Use a Select or segmented control.

## Writing

Label the event, not the control: “Review closes”, not “Time”. Say the time zone in the description (“Local time”, “UTC”). Messages say what to enter: “Use 15 minute steps, for example 09:00.”

## Notes

- `value` is a string `"HH:mm"` (24 hour) or `null`. `min` and `max` use the same form. Steps count from `min` (or midnight).
- `onValueChange` fires as soon as the text is a complete valid time and with `null` when it stops being one.
- `onValidate({ status, message })` reports `empty`, `incomplete`, `valid`, `invalid`, `before-min`, `after-max` or `off-step`. An incomplete time is only called out after the field loses focus.
- The picker does not handle time zones. Store the zone beside the time and say it in the description.

## Screen readers

- A text input named by its Field. The description gives the format, the arrow-key behaviour and the step. On 12 hour fields the AM/PM select is named "AM or PM".
- A problem is linked with `aria-describedby`, shown as text with an icon and announced politely.
- Read-only keeps the value readable and focusable.

## Visual

- Digits use tabular figures. The invalid border is paired with the message and icon. Targets meet the minimum size.
