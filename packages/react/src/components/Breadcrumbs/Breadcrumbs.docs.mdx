## When to use

- On pages two or more levels deep, such as a datapoint inside a disclosure inside a report.
- At the top of the page, above the page title, so people can move up without the back button.

## When not to use

- On top-level pages: there is nothing above them.
- To show the history of pages visited. Breadcrumbs reflect structure, not a session.
- For steps in a process: use a Stepper.

## Content

- Use the same names as the page titles they link to.
- The last item is the current page. It isn't a link.
- Add an icon to the first item only, when it identifies a workspace or entity.

## Notes

- Pass `renderLink` to use your router's link component; it receives `href`, `className`, `onClick`, `title` and `children`.
- Items with `onClick` and no `href` render as buttons. Prefer real links so people can open levels in a new tab.

## Screen readers

- The trail is a `nav` landmark named “Breadcrumb” containing an ordered list, so the number of levels is announced.
- The current page has `aria-current="page"`.
- The collapse button says how many levels it hides, for example “Show 3 more levels”.
- Separators are decorative and hidden from assistive technology.
