## When to use

- For free text of more than a line: explanations, methodology notes, comments.
- With a character count where a limit applies.

## When not to use

- For short answers. Use [Input](/components/input).
- For formatted content. Use a rich text editor.

## Warn, read-only and loading

<Example of="Textarea/StateContract" title="Warn, read-only and skeleton" description="Warn marks a value that is allowed but worth a second look. It is never the same as invalid: it does not set aria-invalid and never blocks submission, and the message carries an icon and text so it is not colour alone. Read-only shows the value flat, keeps it focusable and copyable, and ignores changes. Skeleton replaces the control while its data loads; the label stays for screen readers. Set all three on a Field and every control inside follows." />

Set `warn` (a message), `readOnly` and `skeleton` on the surrounding `Field`. On a standalone text area, pass `readOnly` and `skeleton` directly; give `warn` a message through a Field so it is announced. An error always replaces a warning.

## Notes

- All native textarea props are supported.
- `autoGrow` sets resize to none. `showCount` needs `maxLength` to show the limit.
- Works inside a [Field](/components/field).

## Screen readers

- Announced as a multi-line text box. The count is linked as its description, and within the last 10% of the limit a polite message reports characters left.

## Visual

- Border and focus match Input. Past the limit the count turns the danger colour and heavier weight.
