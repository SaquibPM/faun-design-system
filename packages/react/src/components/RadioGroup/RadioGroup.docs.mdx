## When to use

- For one choice from two to about six options that people should compare.
- When each option needs a description, as with methods or scopes.

## When not to use

- For more than about six options. Use [Select](/components/select).
- For independent options. Use [Checkbox](/components/checkbox).
- For on and off. Use [Switch](/components/switch).

## Writing

Make options parallel and sentence case. Put the default first and preselect it where there is a safe default.

## Warn, read-only and loading

<Example of="RadioGroup/StateContract" title="Warn, read-only and skeleton" description="Warn marks a value that is allowed but worth a second look. It is never the same as invalid: it does not set aria-invalid and never blocks submission, and the message carries an icon and text so it is not colour alone. Read-only shows the value flat, keeps it focusable and copyable, and ignores changes. Skeleton replaces the control while its data loads; the label stays for screen readers. Set all three on a Field and every control inside follows." />

Set `warn` (a message), `readOnly` and `skeleton` on the surrounding `Field`. On a standalone radio group, pass `readOnly` and `skeleton` directly; give `warn` a message through a Field so it is announced. An error always replaces a warning.

## Notes

- `options` are `{ value, label, description?, icon?, meta?, disabled? }`.
- The group takes `label` as its accessible name. Use `hideLabel` only when context makes it obvious.
- `columns` lays cards out in 1, 2 or 3 columns.

## Screen readers

- Announced as a radio group with its label. Each option announces its position, for example “2 of 3”, and its selected state.

## Visual

- Selected radios show a filled centre. Cards add a stronger border and background so selection is clear without colour.
