## When to use

- For products whose top-level areas are few and always visible: Overview, Filings, Data, Agents.
- Together with the side navigation, when the side navigation holds the pages inside the current area.

## When not to use

- For more than five or six links. Move the rest into the side navigation or a sub-menu.
- For switching between sections of one page. Use [Tabs](/components/tabs).
- For switching product or workspace. Use the switcher in the [Header panel](/components/header-panel).

## Small screens

Below 768px the links fold into one Menu button. Sub-menus become labelled groups inside it. Change the breakpoint with `collapseBelow`.

## Writing

Use one word where you can. Sentence case. Name destinations, not actions.

## Anatomy

A navigation landmark with a list of links. The current link is semibold with a 3px underline in the accent colour; sub-menu buttons carry a chevron that turns when open. Menus reuse the standard Menu surface.

## Notes

- Pass `items` as data: `{ label, href, current, children }`. Mark `current` yourself from the route.
- For router links, render the sub-menu or top-level items with your own element and the `faun-header-nav-link` class, or intercept clicks on the `nav`.
- Place it in `TopBar nav`. Give it a `label` when there is more than one navigation landmark with the same role.

## Screen readers

- A `nav` landmark named “Primary”. The current link has `aria-current="page"`. Sub-menu buttons announce that they open a menu and whether it is expanded.

## Visual

- The current page is shown by weight and an underline as well as colour. Link text meets 4.5:1.
