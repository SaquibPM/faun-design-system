## When to use

- For information or controls that belong to the whole product and that people open briefly: notifications, help, the product switcher.
- When the page behind should stay usable while the panel is open.

## When not to use

- For detail about the object on the page. Use a [Sheet](/components/sheet) with `modal={false}`.
- For a decision that must be made first. Use a [Dialog](/components/dialog).
- For a short list of commands. Use a [Menu](/components/menu).

## Behaviour

- One panel is open at a time: opening another closes the first.
- The trigger has an outline while its panel is open, and pressing it closes the panel.
- Escape, a press outside, the close button and choosing a link all close it. Focus returns to the trigger.
- Panels hang from the header and are full width below 768px.

Panel titles are nouns: “Notifications”, “Products”. Action names say what opens: “Switch product”.

## Notes

- Wrap actions in `HeaderActions` to get the one-at-a-time rule. Control it with `openId` and `onOpenIdChange`.
- A `HeaderAction` without a `HeaderPanel` child is a plain icon button; give it `onClick`.
- `badge` is a number, or `true` for a dot. The count is also in the button's accessible name.
- `useHeaderPanel().close()` closes the panel from a custom item. Links inside the panel close it by default (`closeOnSelect`).
- The panel positions against the nearest positioned ancestor; inside `TopBar` that is the bar, which is sticky.

## Screen readers

- Each icon is a button named for what it opens and, with a badge, the count (“Notifications, 2 new”). It reports expanded state.
- The panel is a dialog named by its title. The switcher is a navigation named “Products”, with a heading per section, and marks the current product with `aria-current`.

## Visual

- The open trigger is outlined and tinted as well as expanded, so the connection to its panel is visible. Badges carry a number or a shape, never colour alone.
