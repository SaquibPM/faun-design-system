## When to use

- As the one place events are kept after the [Toast](/components/toast) that announced them has gone: approvals waiting, failed runs, finished exports.
- In the top bar, beside search and the account menu.

## When not to use

- For a condition that affects the current page and stays true until fixed. Use a [Banner](/components/banner).
- For the result of an action the person just took. Use a Toast.
- For every event. Notify only what a person might need to act on or would regret missing.

## Writing

- The title states the event in a sentence: “Ledger import failed”. The text gives the fix.
- Name the source (an agent, a filing) before the time.
- Action labels are verbs and objects: “Review approval”.

## Anatomy

Panel: header with the title, unread count and Mark all as read; a scrolling list with sticky group headings; a footer with links to the full centre and to preferences. Item: tone icon, title, text, source and time, actions, unread dot, dismiss button.

The bell takes its badge from the attention tone, the same one used for “waiting on you”, and shows a count up to 9+.

## Notes

- The panel is controlled by your data: pass `items`, and update them in `onToggleRead`, `onDismiss` and `onMarkAllRead`.
- `group` on an item sets its heading. Items are shown in the order given, so sort newest first.
- Pass `trigger` to replace the bell, for example a header icon from your own shell.
- `NotificationBell` can be used alone when the list lives on another page.

## Screen readers

- The bell is named with the count: “Notifications, 3 unread”. The badge itself is hidden from assistive technology.
- Each notification is a list item named by its title, preceded by its tone and “unread” as words.
- Groups are labelled sections with headings, so people can move between them by heading.

## Visual

- Unread state is a dot, a bold title and the word “unread” for screen readers, not only a tint. In forced colours the dot and a side rule use system colours.
