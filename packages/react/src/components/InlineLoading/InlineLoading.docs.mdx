## When to use

- For a short action on one object: saving a draft, matching rows, syncing a connector.
- When the result should stay next to the control that started it, not interrupt the page.

## When not to use

- For a result people must not miss, such as a failed submission. Use a [Banner](/components/banner) or [Toast](/components/toast).
- For a bare wait with no result to report. Use a [Spinner](/components/spinner).
- When progress is measurable. Use [Progress](/components/progress).

## Writing

Use the same verb through the flow: Saving…, Saved. Say what failed and what to do: “Draft not saved. Try again.”

## Anatomy

An icon (spinner, check or alert) and a text description on one line, in the body-small role. The block keeps a minimum height so layout does not jump when it appears.

## Notes

- Keep the component mounted and change `status` and `description`. A live region that is already in the page announces changes; one that mounts with text may not.
- `onSuccess` fires once, `successDelay` ms (default 1500) after the status becomes `finished`. Use it to return to `inactive`.
- To show the outcome on the button itself, use Button's `status`.

</Section>

<Section tab="accessibility">

## Keyboard

Not interactive.

## Screen readers

- Active and finished text is announced politely (`role="status"`). An error is announced assertively (`role="alert"`).
- Icons are hidden from assistive technology; the description carries the meaning.

## Visual

- Success and danger text meet 4.5:1. The icon changes with the status, so colour is never the only cue.
