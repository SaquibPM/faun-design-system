## When to use

- To pick a reporting date, period start or end, or a due date.
- To pick a range with quick presets for the usual reporting periods.

## When not to use

- For a date far in the past that people know by heart, such as a birth date. Use separate inputs.
- For a time of day. Use [Time picker](/components/time-picker).

## Writing

Label what the date means: “Reporting period”, “Period end”. The placeholder is the format (“dd/mm/yyyy”); do not repeat it in the label. Error messages say what to do: “Enter a date on or after 01/01/2026.”

## Warn, read-only and loading

<Example of="DatePicker/StateContract" title="Warn, read-only and skeleton" description="Warn marks a value that is allowed but worth a second look. It is never the same as invalid: it does not set aria-invalid and never blocks submission, and the message carries an icon and text so it is not colour alone. Read-only shows the value flat, keeps it focusable and copyable, and ignores changes. Skeleton replaces the control while its data loads; the label stays for screen readers. Set all three on a Field and every control inside follows." />

Set `warn` (a message), `readOnly` and `skeleton` on the surrounding `Field`. On a standalone date picker, pass `readOnly` and `skeleton` directly; give `warn` a message through a Field so it is announced. An error always replaces a warning.

## Anatomy

A text field with a format mask and a calendar button at the end, a message line under it for problems, and a raised panel with the month grid. A range has a start and an end field in one box. Range pickers add a presets column that collapses above the calendar on narrow screens.

## Notes

- Dates are `Date` objects. `DateRangePicker` values are `{ from, to }`.
- `entry` is `typed` (default) or `button`. `inputFormat` sets the mask. `dateFormat` only affects `entry="button"`.
- Typing: `onValueChange` fires with a `Date` as soon as the text is a complete, real date inside the limits, and with `null` when it stops being one. A range reports only when both ends are valid and in order.
- `onValidate({ status, message })` reports `empty`, `incomplete`, `valid` or a problem: `invalid`, `before-min`, `after-max`, `disabled`. An incomplete date is only called out after the field loses focus.
- The ref is now the text input (it was the trigger button) unless `entry="button"`.
- `presets` accepts your own list, or `false` to hide them. Set `fiscalYearStartMonth` (1 to 12) for fiscal presets.
- The calendar is styled with Faun CSS. No other stylesheet is needed.

## Screen readers

- The field is a text input named by its Field (a range has two, "start date" and "end date", in a group). Its description gives the format and the Alt + ↓ shortcut. A problem is linked with `aria-describedby`, shown as text with an icon and announced politely.
- The calendar is a grid with day names. The focused day and selected range are announced. Disabled days are announced as unavailable.

## Visual

- Selected days use a fill, not colour alone. Today is marked with bold text and a dot. Day targets meet the minimum size.
