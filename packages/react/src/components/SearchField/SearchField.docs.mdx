## When to use

- To filter a list or table by typing.
- To search a workspace, with a shortcut such as ⌘K.

## When not to use

- For a form value. Use [Input](/components/input).
- To pick from known options. Use [Combobox](/components/combobox).

## Writing

Placeholder names what is searched: “Search by site, factor or run ID”. Empty results say what to try next.

## Warn, read-only and loading

<Example of="SearchField/StateContract" title="Warn, read-only and skeleton" description="Warn marks a value that is allowed but worth a second look. It is never the same as invalid: it does not set aria-invalid and never blocks submission, and the message carries an icon and text so it is not colour alone. Read-only shows the value flat, keeps it focusable and copyable, and ignores changes. Skeleton replaces the control while its data loads; the label stays for screen readers. Set all three on a Field and every control inside follows." />

Set `warn` (a message), `readOnly` and `skeleton` on the surrounding `Field`. On a standalone search field, pass `readOnly` and `skeleton` directly; give `warn` a message through a Field so it is announced. An error always replaces a warning.

## Anatomy

A search icon, the text input, a loading spinner or clear button and an optional shortcut hint (Kbd). Search fields have a type of search and are always named.

## Notes

- `onValueChange` fires as people type. `onSearch` fires when they press Enter.
- Search fields need an accessible name: pass `aria-label` or put them in a Field. The placeholder is the fallback name.
- `shortcut` is a hint only. Bind the key yourself, or use the [Command palette](/components/command-palette).
