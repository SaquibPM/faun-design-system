## When to use

- Under tables and lists with more rows than fit on one screen, where people need to find a position (“page 12”).
- When the total is known and the list is stable while someone browses it.

## When not to use

- For fewer items than one page: hide the control.
- For feeds or logs people read top to bottom: use load more or infinite scroll.
- For unknown totals: use previous and next only (`variant="compact"`) and omit the summary.

## Anatomy

Page size picker, range summary, then previous, numbered pages and next, aligned to the end. The current page has a border and semibold weight. Numbers use tabular figures and thousands separators.

## Notes

- Fully controlled: you own `page` and `pageSize`. Reset to page 1 when the page size or filters change.
- The page size picker is a native select, which keeps it fast and accessible on touch.
- `paginationRange` is exported if you need the same page list elsewhere.

## Screen readers

- A `nav` landmark named “Pagination”. Page buttons are named “Page 3” and the current one has `aria-current="page"`.
- The range summary is a polite live region, so changing page announces “Showing 26–50 of 1,034”.
- Disabled previous and next stay in the tab order flow as disabled buttons.
