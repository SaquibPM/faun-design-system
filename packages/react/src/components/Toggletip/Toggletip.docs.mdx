## When to use

- For optional detail beside a label or a figure: how a score is calculated, what a field is for.
- When the explanation is more than a phrase, or needs a link such as “How it is calculated”.
- When the content must be reachable on touch screens, where hover does not exist.

## When not to use

- To name an icon-only control. [Tooltip](/components/tooltip) does this, and Icon button includes one.
- To explain a single term inside a sentence. Use [Definition tooltip](/components/definition-tooltip).
- For anything a person must read to finish the task. Put it on the page.
- For a form or several actions. Use a [Popover](/components/popover) or a Dialog.

## Writing

- Start with the answer. Two sentences at most; link out for more.
- Name the button for what it explains: “About evidence coverage”, never just “Info”.

## Notes

- Built on Popover: `open`, `defaultOpen` and `onOpenChange` control it.
- `label` names the button and the panel. Always set it to something specific.
- `icon` is `info`, `help` or your own element.

<Keys rows={[["Enter or Space", "Opens the panel from the button, and closes it again."], ["Tab", "Moves into the panel to links and buttons, then on to the next control."], ["Escape", "Closes the panel and returns focus to the button."]]} />

## Screen readers

- The button is announced with its name and expanded or collapsed. The panel is a dialog with the same name; focus moves into it so its text is read.

## Visual

- The panel has a border as well as a shadow so it stays visible in high-contrast themes. The button meets the minimum target size.
