## When to use

- For lists of more than about 15 options, or when people know part of the name.
- When options need a second line, such as a factor value or a unit.
- For server-side search with a loading state.

## When not to use

- For a short list. Use [Select](/components/select).
- For several values. Use [Multi select](/components/multi-select).
- For free text where the list is only a hint and most answers are new. Use an Input; use a combobox with `allowCustomValue` when the list is the main route.

## Writing

Placeholders say what can be searched: “Search 4,000 factors”. The empty message says what to try next.

## Warn, read-only and loading

<Example of="Combobox/StateContract" title="Warn, read-only and skeleton" description="Warn marks a value that is allowed but worth a second look. It is never the same as invalid: it does not set aria-invalid and never blocks submission, and the message carries an icon and text so it is not colour alone. Read-only shows the value flat, keeps it focusable and copyable, and ignores changes. Skeleton replaces the control while its data loads; the label stays for screen readers. Set all three on a Field and every control inside follows." />

Set `warn` (a message), `readOnly` and `skeleton` on the surrounding `Field`. On a standalone combobox, pass `readOnly` and `skeleton` directly; give `warn` a message through a Field so it is announced. An error always replaces a warning.

## Notes

- `options` are `{ value, label, description?, icon?, group?, keywords?, disabled? }`.
- Value is a string or `null`. Use `clearable` to let people reset it. Emptying the text and leaving the field also clears the value.
- The field is the search input. Filtering is local and matches label, description and keywords; set `filter={false}` and use `onSearchChange` when the server filters.
- `allowCustomValue` is opt in. Typed text that exactly matches an option label (ignoring case) selects that option; other text is committed as given, and the list shows a "Use ..." row (`customValueLabel`). Validate custom values yourself and show the result through `Field`.
- The ref is now an `HTMLInputElement` (it was a button). `searchPlaceholder` is ignored; put the hint in `placeholder`.
- Works inside a [Field](/components/field), which supplies the label and error.

## Screen readers

- The input has role combobox with `aria-expanded`, `aria-controls`, `aria-autocomplete="list"` and `aria-activedescendant` pointing at the highlighted option, so focus never leaves the field. Options are `role="option"` with `aria-selected`, in a labelled listbox; groups are labelled groups.
- A polite live region announces the number of options as you type, or "No matches". The chevron and clear buttons are named ("Show options", "Clear Diesel").
- Read-only keeps the value readable and focusable and never opens the list.

## Visual

- Focus shows a ring and halo on the field. The highlighted option has a background change and a visible outline in forced-colours mode.
