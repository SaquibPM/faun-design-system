## When to use

- To show the detail of a row or object while keeping the list in place: a datapoint, a run, a tool's schema.
- For filters and editors that need more room than a popover but shouldn't replace the page.
- As a non-modal inspector beside a canvas, such as a task graph or an artifact preview.

## When not to use

- For a short decision or confirmation: use a Dialog or Alert dialog.
- For primary content people return to: give it its own page with a URL.
- For a few options: use a Popover or Menu.

## Anatomy

A header (title, description and optional meta such as status badges), a scrolling body, and an optional footer with actions, separated by subtle borders. Right and left sheets are full height; bottom sheets have rounded top corners.

## Sizes

Small 400px, medium 560px (default) and large 760px. Sheets never exceed the viewport width.

## Notes

- `modal` is set on `Sheet`, not on the content. Non-modal sheets ignore outside clicks; close them with the close button or Escape.
- `SheetHeader` provides the accessible title. Always include one.
- Content scrolls inside `SheetBody`; the header and footer stay put.

## Screen readers

- The sheet has the `dialog` role named by its title. Modal sheets also set `aria-modal` and hide the rest of the page from assistive technology.
- Non-modal sheets leave the page available, so give them a clear title that says what they inspect.

## Visual

- The sheet edge carries a 1px border as well as a shadow, so it stays visible in high-contrast themes.
- Motion uses the emphasized easing for 300ms on entry and is removed when reduced motion is requested.
