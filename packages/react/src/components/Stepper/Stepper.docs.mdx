## When to use

- For a process with a fixed order and a clear end: filing a report, importing data, onboarding a framework.
- To show where an agent's workflow is paused for a human.

## When not to use

- For sections people can visit in any order: use Tabs.
- For more than six steps: group them, or show progress with a Progress bar.
- For a single long operation: use Progress.

## Anatomy

A numbered marker, label, optional description and a connector to the next step. Complete steps show a check and an accent connector; errors show a cross; awaiting-human shows a person.

## Responsive

On narrow screens horizontal steppers show markers only, with the current step's text expanded.

## Notes

- The component is display-only; you own the current index. Set `state` on a step to override what is derived.
- Pair with a heading that names the process, and pass `aria-label` for the list.

## Screen readers

- An ordered list; the current step has `aria-current="step"`.
- Each step includes status text (“Completed”, “Current step”, “Not started”, “Needs attention”, “Waiting for a person”, “Unavailable”), hidden by default and shown with `showStatus`, so state never depends on colour or icon alone.

## Visual

Markers use distinct glyphs per state, and colours meet contrast on both themes.
